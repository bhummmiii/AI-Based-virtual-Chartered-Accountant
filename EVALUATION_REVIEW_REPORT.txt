EXECUTIVE SUMMARY
----------------------------------------------------------------------------------------------------
The AI-Based Virtual Chartered Accountant is an end-to-end intelligent financial technology platform 
designed to automate the core workflows of Chartered Accountants, tax practitioners, and enterprises. 
It replaces manual, error-prone data entry with a multi-tiered Artificial Intelligence pipeline that 
ingests, analyzes, reconciles, and extracts structured financial, GST, and accounting data from 
heterogeneous multi-page documents (invoices, credit/debit notes, GST challans, e-way bills, and 
statutory notices).

Below is the exhaustive, criterion-by-criterion technical breakdown tailored precisely to the 
evaluation rubric parameters.

3. EFFICIENCY ISSUES IDENTIFIED & TECHNICAL SOLUTIONS IMPLEMENTED
----------------------------------------------------------------------------------------------------
A. Issue 1: Multi-Page Truncation in Standard OCR Pipelines
   - Problem: Standard OCR libraries and naive API calls typically process only the first 1 to 3 pages 
     to save bandwidth, completely omitting line items on intermediate pages and critical tax summaries 
     and grand totals on the final page.
   - Solution: Implemented a dynamic multi-page batch rendering pipeline using PyMuPDF pixmaps supporting 
     up to 20 pages per document. All pages are passed concurrently to the multimodal context window, 
     enabling comprehensive line item extraction across pages 1-4 and tax breakdown from page 6.

B. Issue 2: OCR Label Collision & False Overwrites
   - Problem: Noisy OCR frequently misidentifies document structural labels as entity names 
     (e.g., capturing "Buyer (Bill to)" as the customer name, or "HSN/SAC No." as the HSN code "No.").
   - Solution: Engineered a multi-stage validation layer featuring:
     * A strict reject vocabulary (_GENERIC_REJECT_SET) discarding structural labels.
     * Look-ahead line inspection resolving the actual entity name (e.g., "VARDHMAN AGRO SERVICES").
     * Strict regex validation enforcing 4 to 8 numeric digits for HSN/SAC codes.

C. Issue 3: Discrepancy Between Tax Sums and Gross Invoice Amounts
   - Problem: Simple regex scanners frequently capture the Tax Subtotal (e.g., Rs. 1,49,636.90) as the 
     Grand Total, resulting in an erroneous Taxable Value calculation of 0.00.
   - Solution: Implemented an intelligent mathematical reconciliation rule:
       Grand Total = Taxable Value + CGST + SGST + IGST + Cess + Round Off
     The system prioritizes verified last-page calculation summaries, guaranteeing financial consistency.

D. Issue 4: API Model Deprecations & High Cloud Credit Consumption
   - Problem: Deprecation of legacy LLM models (e.g., gemini-2.5-flash) causing 404 errors, coupled with 
     high credit costs if repetitive OCR is executed on every document view.
   - Solution: Implemented a robust model fallback hierarchy (gemini-3.6-flash -> gemini-3.8-flash -> 
     gemini-3.7-flash -> gemini-1.5-flash) combined with permanent metadata caching in PostgreSQL. 
     Documents are processed once upon upload/scan; subsequent views load instantaneously from DB cache.

CRITERION 2: TOOLS AND TECHNIQUES USED (10 MARKS)
====================================================================================================

1. PROGRAMMING LANGUAGES & FRAMEWORKS
----------------------------------------------------------------------------------------------------
- Python 3.10+: Primary backend language chosen for its rich ecosystem in AI, computer vision, and math.
- TypeScript (ES2022+): Frontend programming language delivering strict compile-time type safety.
- FastAPI: High-performance, async-first Python web framework utilizing Starlette and Pydantic.
- Next.js 14 / React 18: Modern component-driven UI architecture delivering dynamic state management.

2. DATABASE, STORAGE & DATA MODELING
----------------------------------------------------------------------------------------------------
- PostgreSQL: Enterprise relational database providing ACID compliance, foreign key cascades, and 
  JSONB-compatible schema storage for flexible metadata.
- SQLAlchemy 2.0: Python Object-Relational Mapper (ORM) managing relational schema definitions.
- Client-Isolated Storage Architecture: Uploaded files are partitioned physically into isolated client 
  directories ('uploads/<client_id>/<uuid>.<ext>'), ensuring strict multi-tenant data segregation.

3. ARTIFICIAL INTELLIGENCE, COMPUTER VISION & OCR TECHNIQUES
----------------------------------------------------------------------------------------------------
- Google Gemini Vision API (Multimodal Large Language Model):
  * Employs Multimodal Zero-Shot / Few-Shot Prompt Engineering.
  * Ingests high-resolution rendered document page streams and produces structured JSON conforming 
    strictly to Indian GST tax structures, line-item arrays, and HSN summary matrices.
- PyMuPDF (fitz): High-speed PDF rasterization, text vector extraction, and bounding-box table extraction.
- Tesseract OCR (v5.x): Local optical character recognition engine acting as an on-premise fallback.
- OpenCV (cv2) & Pillow (PIL): Image preprocessing pipeline:
  * Grayscale conversion and bilateral filtering for noise removal.
  * Otsu and Adaptive Gaussian thresholding to eliminate shadows and background gradients.
  * Deskewing via affine transformations and orientation detection (OSD).

4. INFORMATION EXTRACTION & FINANCIAL RECONCILIATION TECHNIQUES
----------------------------------------------------------------------------------------------------
- Hybrid Two-Stage Extraction Pipeline:
  * Stage 1: Ultra-fast local regex and vector table parser (<350ms) for high-confidence documents.
  * Stage 2: Deep Multimodal AI Vision Fallback triggered for scanned, photographed, complex, or multi-page docs.
- GSTIN & PAN Entity Normalization:
  * Indian GSTIN format regex: ^[0-9]{2}[A-Z]{5}[0-9]{4}[A-Z][1-9A-Z]Z[0-9A-Z]$
  * PAN extraction: 10-character alphanumeric regex derived directly or parsed from characters 3–12 of GSTIN.
- Rate-Wise HSN/SAC Summary Decomposition:
  * Parses multi-tier tax rate tables (e.g., 9% CGST + 9% SGST = 18% Total Tax).
  * Automatically cross-checks line-item sum against document-level grand totals.

5. USER INTERFACE & VISUAL DESIGN TECHNIQUES
----------------------------------------------------------------------------------------------------
- Glassmorphic Financial Dashboard: Custom dark-mode interface designed with curated HSL color tokens.
- Split-View Document Modal: Dual-pane interface displaying extracted structured data tables on the left 
  and a synchronized live canvas PDF/image preview on the right.
- Asynchronous File Streaming: Authenticated blob streaming mechanism allowing real-time document 
  downloads with proper MIME types and original file names.
